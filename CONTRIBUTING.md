# Contributing

## Pull requests
- Keep changes focused and describe the user or API behaviour covered.
- Add or update tests with every behaviour change.
- Do not commit credentials, tokens, personal data, browser profiles or generated reports.
- Run the relevant test suite and static checks before opening a pull request.
- Include test evidence and known limitations in the pull request description.

## Coding standards
- Prefer readable names and small, single-purpose methods.
- Keep selectors and interaction logic in page objects.
- Avoid fixed sleeps; use condition-based waits.
- Keep test data independent and clean up any data created by a test.
